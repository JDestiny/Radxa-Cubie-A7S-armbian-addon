# 温度传感器与风扇 —— 板级实测结论（2026-09-14）

> **起因**：htop / thermal_zone 里有一条 `skin_zone`（"外壳/板面"，crit 50 °C），追问它到底是哪个传感器、装在哪、
> 会不会真的把整机热关机；顺带把 CPU 大小核与热区命名的对应、以及风扇调速脚本一起核实了。
>
> **一句话结论**：**板上没有任何温度器件**；"skin" 是驱动用**大核温度 ÷5** 合成的**虚拟值**，它那条 50 °C critical
> 对应真实大核 ~160 °C，**实际永远轮不到**；而 DTS 里 `cpub`/`cpul` 两个**主热区的名字与真实簇是反的**
> （跟用户手册一致、跟实测相反）。风扇由用户态服务 `fanctl` 独占控制（所有热区 policy = `user_space`）。
>
> 环境：Radxa Cubie A7S · 内核 `6.6.98-vendor-sun60iw2` · 实测日期 2026-09-14

---

## 一、板上没有温度传感器（电路图证据）

- 电路图 `doc-a7s/radxa_cubie_a7s_schematic_v1.10.pdf`（16 页）全文文本提取后搜索：
  `thermistor|ntc|lm75|tmp1|sht|dht|温度` → **0 命中**；`ths|therm|temp|ptat` → **0 命中**。
- 风扇所在页（`16 KEY_LED_FAN`）只有 3 脚接插件 `J7`（`VCC5V0_SYS` / GND / `PJ27_PWM1-9` 来自 SoC PWM1），
  **没有转速回读线** —— 与"读不到 `fan1_input`"完全一致。
- ⇒ 所有温度都来自 **SoC 内部 THS**：`/proc/device-tree/soc@3000000/ths@2522000`，`compatible = allwinner,sun60iw2p1-ths`。
- 想要真正的"壳温"只能外加：I²C 温度芯片（LM75/TMP112…）、NTC + SoC GPADC 通道，或用红外测温枪标定
  "外壳温度 ≈ 大核温度 + 偏置"的经验关系。

## 二、SoC 里到底有几个传感器

- **数据手册 §3.9.8**：*Five thermal sensors, respectively distributed in A76 core, **A56** core, GPU, NPU and DDR.*
  （A733 小核是 A55，"A56" 应为笔误；用户手册同一处写的是 CPUL。）
- **用户手册 §7.1.1（原文，注意与实测相反）**：
  > Sensor0 is located in the **CPUB**; sensor1 is located in the **DDR**; sensor2 is located in the **NPU**;
  > sensor3 is located in the **CPUL**; sensor4 is located in the **GPU**.
- **内核驱动** `build/.../bsp/drivers/thermal/sunxi_thermal.c`：`sun60iw2p1_ths.sensor_num = 8`，
  其中 **5/6/7 是虚拟传感器**（硬件只有 5 路）：

```c
enum virtual_sensor { cpul_idle_sensor = 5, cpub_idle_sensor = 6, skin_virtual_sensor = 7 };
#define CPUL_SENSOR_NUM (0)
#define CPUB_SENSOR_NUM (3)
```

## 四、实测证据（两条独立证据链）

### 4.1 位级相等 —— 证明虚拟传感器的路由

```
cpul_idle_zone(虚拟5) ≡ cpub_thermal_zone(通道0)      36.21==36.21  34.60==34.60
cpub_idle_zone(虚拟6) ≡ cpul_thermal_zone(通道3)      39.06==39.06  33.85==33.85
skin = compress(通道3)：39.06→31.81（实测 31.81）、33.85→30.77（实测 30.77）
```

同一时刻两个不同 zone 的读数**逐位相同** ⇒ 它们读的是同一个硬件寄存器，虚拟通道 5/6/7 的路由确认。

### 4.2 taskset 交叉实验 —— 证明"通道 ↔ 簇"

前提（运行中设备树 + 内核视图）：`cpu@0..500 = arm,cortex-a55`（capacity 385、1.794 GHz）、
`cpu@600/700 = arm,cortex-a76`（capacity 1024、2.002 GHz）→ **cpu6,7 是大核**。

设计：`L-B-L-B` 交叉（消顺序偏差），每相 30 s（从低温起步，尽量不让风扇介入），
采样进程用 bash 内建 `$(<file)` 零 fork，并**钉到当前空闲的核**（大核相钉 cpu1、小核相钉 cpu7），2 s 采样。

判据 `D = Δ(cpub_thermal_zone) − Δ(cpul_thermal_zone)`：

| 相位 | 负载 | D | 结论 |
|---|---|---|---|
| L1 | cpu0-5（A55 小核） | **+0.56** | `cpub` 通道（id 0）响应更强 |
| L2 | cpu0-5 | **+0.17** | 同上 |
| B1 | cpu6,7（A76 大核） | **−1.59** | `cpul` 通道（id 3）响应更强 |
| B2 | cpu6,7 | **−0.94** | 同上 |

两次重复、两种顺序方向一致 ⇒ **通道 0 属于 A55 小核、通道 3 属于 A76 大核**。
（采样进程自热的方向与观测相反，因此结论偏保守；小核相全程 `pwm=50`，无风扇干扰。）

> 原始数据与脚本：`/tmp/thermal-test/{samples.csv,round2.csv,round3.csv,run*.sh,zones.txt}`（临时件，重启即失；方法见第九节）

## 五、`skin_zone` 到底是什么（那条 50 °C 的真相）

驱动源码（`sun60iw2_ths_get_temp()` 的 `skin_virtual_sensor` 分支）：

```c
/* 读的是通道 3（常量名 CPUB_SENSOR_NUM，实测=大核）*/
regmap_read(..., temp_data_base + 0x4 * CPUB_SENSOR_NUM, &val);
*temp = sun60iw2_calc_temp(tmdev, CPUB_SENSOR_NUM, val);
if (*temp <= 30000)       *temp = 30000;                          /* 30 °C 下限钳位 */
else if (*temp <= 100000) *temp = 30000 + (*temp - 30000) / 5;     /* 30~100 °C → 压成 30~44 */
else                      *temp = 44000 + (*temp - 100000) / 10;   /* >100 °C → 慢涨 */
```

也就是 **skin = max(30, 30 + (大核温度 − 30)/5)**，一个**伪表面温度**：

| 真实大核 | 30 | 40 | 50 | 60 | 100 | 110 | **160** |
|---|---|---|---|---|---|---|---|
| `skin_zone` 显示 | 30 | 32 | 34 | 36 | 44 | 45 | **50**（=crit） |

**反解**：skin 要触发 50 °C 的 critical → 需要真实大核 **≈160 °C**；而大核自己的 critical 是 110 °C
（`cpul_thermal_zone`，且因为 policy=user_space，内核也不降频）——所以**这条 50 °C 保护线永远轮不到触发**，
它是 vendor 给上层（Android thermal HAL）看的"体感温度"模型，不是可用性上限。

**实测吻合**：34.04→30.81、39.06→31.81，逐位精确；2h 满载（大核峰值 46.3）时 skin 峰值 33.1 也符合公式。

## 六、CPU 大小核与命名错位（vendor 三处不一致）

| 来源 | 声称 | 与实测 |
|---|---|---|
| A733 用户手册 §7.1.1 | ch0 = CPUB（大核）、ch3 = CPUL（小核） | ❌ 相反 |
| DTS `sun60iw2p1.dtsi`（主热区名） | `cpub_thermal_zone`→ch0（且绑 `cpufreq-cpu6` 大核） | ❌ 名字相反（传感器实为小核） |
| 驱动常量 | `CPUL_SENSOR_NUM=0`、`CPUB_SENSOR_NUM=3` | ✅ 与实测一致 |
| **实测（taskset 交叉实验）** | **ch0 = A55 小核、ch3 = A76 大核** | — |

**影响**：

1. **读温度别看名字**：真实**大核**温度看 `cpul_thermal_zone`，**小核**看 `cpub_thermal_zone`（正好反着）。
   两个 idle 别名反而名字是对的：`cpul_idle_zone`＝小核、`cpub_idle_zone`＝大核。
2. **主热区的降频目标是错配的**：`cpub` 区（实为小核传感器）绑 `cpufreq-cpu6/7`（大核），
   `cpul` 区（实为大核传感器）绑 `cpufreq-cpu0-5`（小核）→ **若把 policy 改回 `step_wise`，
   会变成"小核烫了降大核频、大核烫了降小核频"。要恢复内核控温，得先修这两条 cooling-map。**
3. 两个 idle 区的绑定是自洽的（小核↔idle-cpu2..5、大核↔idle-cpu6,7），不用动。
4. `gpu_thermal_zone` 的 passive@60/90 两条 trip **没有绑任何冷却设备**（cdev=0），是空设。

## 七、风扇：现状与两条路线

### 7.1 现状（用户态服务独占）

| 项 | 内容 |
|---|---|
| 控制程序 | `~/fan/fanctl.sh`（部署在 `/opt/fanctl/fanctl.sh`，与仓库版 `diff` 一致） |
| 服务 | `fan-control.service`：`Type=simple`、`Restart=on-failure/RestartSec=10`、`ExecStop=fanctl.sh --stop`（停止时置 PWM 170 安全档）、**enabled，已运行 5 天** |
| 曲线（drop-in） | `LEVELS=50 102 170 255 255`（档 0 也保持最低风量 50）、`UP=38 48 54 60`、`DOWN=35 36 50 56` |
| 调参依据 | `data/loadtest.csv`（空闲 31.4 / 轻载 37.8 / 满载 43.0，峰值 46 °C）；**主动弃用**了 `tune.sh` 自动生成的 DOWN=32（低于空闲地板 → 会卡在 1 档不回落） |
| 设备发现 | 扫 hwmon `name` 含 `pwm`+`fan` 取 `pwm1`；温度源默认取**全部热区最高值** |
| 关键动作 | 启动时把**所有热区 policy 设为 `user_space`** → 内核 governor 不再动冷却设备（critical 关机保护不受影响） |
| 其它 | 只读 `--status`（任何用户可跑，会从 `systemctl show` 读服务实际加载的曲线）；启动归一化写 255 再写目标档（"kick"） |

### 7.2 `pwm1_enable` 不是"手动/自动"开关（容易误解）

驱动自带文档（`Documentation/hwmon/pwm-fan.rst`）：`pwm1_enable` 只定义 **`pwm1=0` 时的电源行为**
（0=关 PWM 与稳压器；1=关 PWM 保稳压器；2/3 保 PWM；…）。代码里唯一会"忽略写入"的是模式 **0**
（`if (ctx->enable_mode == pwm_off_reg_off) return 0;`）——所以**模式 1/2/3 下内核 thermal 与用户态写入都能生效**，
区别只是在 `pwm1=0` 时是否保留稳压器。当前模式 1 与"谁控制转速"无关。

同理"kick"（先写 255）：本内核的 `__set_pwm()` **没有等值早退**（只有 cooling 路径的 `set_cur_state` 有），
所以当前是**多余但无害**的防御性写法；换内核若遇到等值早退的实现就有用。

### 7.3 另一条路线：DTS cooling-map（与现状二选一）

DTS 里给某个热区加 trip + cooling-map，内核就会自动拉风扇档位，例如：

```dts
skin_zone {
    trips {
        skin_warm: skin_warm { temperature = <42000>; type = "active"; };
        skin_hot:  skin_hot  { temperature = <46000>; type = "active"; };
        skin_crit: skin_crit { temperature = <50000>; type = "critical"; };
    };
    cooling-maps {
        map0 { trip = <&skin_warm>; cooling-device = <&pwm_fan 2 3>; };
        map1 { trip = <&skin_hot>;  cooling-device = <&pwm_fan 4 4>; };
    };
};
```

⚠️ 但**当前配置下它不会生效**：`fanctl` 把 policy 全设成 `user_space`，内核 governor 不参与。
要走这条路必须 `FAN_POLICY=0`（或停服务）并接受"内核独占"，而且**必须先修好第六节的 cpufreq 错配**。
本板的 `pwm-fan` 已经是 cooling device（`cooling_device8`，0–4 档，`cooling-levels=<0 50 102 170 255>`），
`#cooling-cells=<2>` 也已具备——缺的只是"谁拥有它"的决定。

### 7.4 现有脚本的小问题（不影响使用）

- 曲线首档阈值 38 °C 距空闲地板（~34 °C）仅 4 °C → 十几秒的短忙就会升到 1 档再落回，日志里可见 3~4 分钟一轮的 0↔1 档摆动；
  想更稳可把 `FAN_UP` 首值抬到 40 或 `FAN_DOWN` 抬到 36~37。
- 头部注释写 `CDEV` 用于"状态查询/兜底写入"，实际只用于 `--status` 显示（无写入路径）。
- 5 天累计 CPU 1h20m（≈1.1% 单核）；每 tick 8 次 `cat`，可用 `$(<file)` 减 fork。
- `ExecStop` 后 policy 仍是 `user_space` → 手动 stop 服务会留下"风扇固定在 170、无人调速"的状态。

## 八、对 24/7 运行的实用结论

1. **不要拿 `skin_zone` 当壳温**（它是大核 ÷5 的伪值），也不要指望它保护整机。
2. 真正要盯的是 5 路物理通道：`cpul_thermal_zone`（实为大核）、`cpub_thermal_zone`（实为小核）、gpu/npu/ddr；
   CPU 两路的 **passive@60 °C 触发降频、active@60 °C 触发风扇**（**当前被 user_space 关掉**），关机线是 110 °C。
3. 进壳运行前想清楚散热：**板上没有壳温感知**，唯一办法是外加传感器或标定经验关系；
   风扇曲线可按壳内实测重新标定（现有曲线是裸板数据）。
4. 若希望在高温下有"降频兜底"而内核又不接管：可在 `fanctl.sh` 里加一条软降频
   （超阈值写 `/sys/devices/system/cpu/cpufreq/policy*/scaling_max_freq`），无需重编内核。
5. 若决定交回内核：修 DTS（① 主热区命名/绑定按实测纠正；② 给风扇补 active trip）→ 重编 → `FAN_POLICY=0`。

## 九、复现方法

```bash
# 通道 → 簇（交叉对照，需 root 免；普通用户即可）
#   负载: taskset -c 6,7 sh -c 'while :; do :; done'   (大核)
#         taskset -c 0-5 sh -c 'while :; do :; done'   (小核)
#   采样: bash 内建 $(</sys/class/thermal/thermal_zoneN/temp)   # 零 fork
#   判据: D = Δ(cpub_thermal_zone) − Δ(cpul_thermal_zone)
#         小核负载 D>0、大核负载 D<0  ⇒ 通道0=小核、通道3=大核

# 别名/虚拟传感器路由（位级相等）
for z in /sys/class/thermal/thermal_zone*; do printf '%s=%s ' "$(cat $z/type)" "$(cat $z/temp)"; done; echo
# 期望: cpul_idle_zone == cpub_thermal_zone 且 cpub_idle_zone == cpul_thermal_zone（同刻读数相同）

# skin 公式核对
#   compress(t) = t<=30 ? 30 : (t<=100 ? 30+(t-30)/5 : 44+(t-100)/10)
#   实测值应与 compress(cpul_thermal_zone) 完全相等

# 电路图无温度器件
pdftotext -layout doc-a7s/radxa_cubie_a7s_schematic_v1.10.pdf - | grep -icE "thermistor|ntc|lm75|tmp1|sht|温度"   # → 0
```
